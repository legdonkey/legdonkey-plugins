# 分镜与视觉规范

主会话在搭场景前写 `video/STORYBOARD.md`。场景子代理只看这份文件和 `scene-authoring.md` 干活，
所以分镜里要写清"画面上出现什么、在说到哪个词时出现、怎么动、怎么转到下一场"。屏幕上的事实性文字要原样写进分镜，不要留给子代理自己发挥。

## STORYBOARD.md 的结构

1. **开头**：片子回答什么问题；声明"旁白是时钟"；列出 `assets/data/` 下三个数据文件的用途；写明换算公式"场景内时间 = 绝对时间 − visualStart"。
2. **§1 视觉系统**：气质、色板（与 `design.json` 一致）、字体、字号、常驻层、动效规范、转场清单。下面的默认值可以直接抄，按主题调整。
3. **§2 工程结构**：场景文件位置、宿主规则、0.6s 重叠的分工。
4. **§3 场景时间表**：场景 id、名称、visualStart、visualEnd、时长、旁白段号。从 `timeline.json` 生成，并注明以 JSON 为准。
5. **§4 音效提示格式与规则**。
6. **§5 逐场景导演说明**。

## 默认视觉系统（§1 可直接用）

**气质**：深色、克制、精密，像 Apple / Linear / Vercel 发布会上的产品讲解片。大面积留白，细线条，少量高饱和强调色。
不要用：项目符号幻灯片、圆圈里的图标、三张并排卡片、整张图一次性出现、emoji。

**色板**：中性色写在 `design.json` 的 `palette` 里，章节强调色写在 `chapters[].color` 里（CSS 变量是 `--c1…--cN`）。
每章只用自己的强调色作为唯一高亮，一个画面最多 1–2 处高亮。`--ok` 表示正确或通过，`--bad` 用于删除线和错误。

**字体**：
- 中文：Noto Sans SC（400/500/700/900），由 `setup_fonts.sh` 准备。
- 西文、数字：Inter（HyperFrames 内置）。
- 代码、命令、文件名：JetBrains Mono（内置）。

**字号**（1080p）：主标题 84–120px（900 粗）；场景标题 56–72px；正文标签 30–40px；代码 26–32px。中文标题字距 `-0.02em`。

**动效**（以 HyperFrames `references/motion.md` 为准）：
- 入场用长尾缓出（`expo.out` / `power4.out`），0.5–0.9s。退场比入场短 40–50%，用 `power3.in`。
- 相关元素重叠出现：前一个完成 30–50% 时，下一个开始。列表项错开 40–80ms，词错开 60–120ms。
- 标题落定后保持静止，运动交给下一个元素或背景。不要让标题呼吸、漂浮或持续缩放。
- 每个场景至少有一个"会动的机制"，让画面解释内容，而不是摆字。例如：线条描绘、数据光点流动、节点逐个点亮、文字改写、时间轴伸缩。
- 快速位移加 6–12px 的运动模糊。
- 所有随机量用固定种子。

**转场**：相邻场景在时间上重叠 0.6s。全片用 4–5 种有原因的转场轮换，不要全片都用同一种淡入淡出：
- **对象变世界**：上一场景里的某个卡片或胶囊放大溢出画面，它的填充色成为下一场景的底。
- **形变**：一个容器的宽度或形状变成下一场景的主容器。
- **横向甩切**（whip）：0.2–0.3s 的水平拖影，新元素带模糊落位，0.13s 后变清晰。
- **光圈**：`clip-path: circle()` 从某个被点亮的点展开。分镜里写明圆心坐标，前后两个场景用**同一个圆心**：前一场景从退场起点（VDUR）开始，在 0.3s 内收拢完（`power3.in`），到 VDUR+0.3 整体 opacity 归零；下一场景从同一圆心展开。下一场景的章节卡 0.35s 后才入场，避免压在前一场景的残留上。
- **模糊互换**：在同一舞台上，旧元素以 8px 模糊淡出，新元素模糊进入，背景不切。

章节之间用最重的转场（对象变世界或光圈），并配大号章节卡。

**章节卡**（全片统一，由不同代理做的章节也一样）：画面中央上下两行，上行章节号（Inter 900，140px，章节色），下行章节名（Noto Sans SC 900，72px，`--ink`）。0.35s 模糊入场；0.9s 起缩到 0.2 倍移向左上角 `(96, 60)`；1.45s 前淡完，之后由 HUD 接手。分镜 §1 照抄这一段，写章节卡的代理之间不需要再互相对齐。

**不用 CSS 3D**：`perspective`、`preserve-3d`、`backface-visibility` 会让整片退回慢速截图渲染（上次整片走了截图模式，5 分钟的片子抓帧用了 15 分 44 秒）。等轴测用 2D 合成：外层 `scaleY 0.574`，内层旋转 −35°。卡片翻面用 `scaleX` 1→0→1，在 0 点换内容。

## §4 音效提示（sfx-cues）

场景作者写 `sfx-cues/<场景 id>.json`：

```json
[{"t": 0.12, "file": "whoosh-short.mp3", "gain_db": -6, "why": "卡片甩入"}]
```

- `t` 是场景内秒数，指画面动作到位的那一帧。混音时，音效峰值会对齐到它之后一帧。
- 可用文件在 `assets/sfx/`（见 `manifest.json`）。
- 每个音效都要有画面上的原因：转场用 whoosh，徽章和数字落位用 pop。
- 全片只用一次 riser + impact，放在总结时刻：riser 写在前一场景，用 `"pre": 3.7` 让峰值落在下一场景开头的 impact 上。
- 一个场景 0–4 个音效就够，宁少勿多。
- 打字声、按键声和旁白抢同一频段，混音时默认删掉，不要依赖它们。

## §5 导演说明的写法

每个场景一节，标题写"场景 id、名称、起止时间"。约定：
- 引号里的文字是屏幕上要出现的原文，保持专有名词的大小写。
- `⟨词⟩` 表示这个元素在旁白说到该词时出现。
- 最后一行写退场方式，并说明它和下一场景入场的衔接（"承接物"是什么）。
- 长场景（> 20s）分成几拍写，要求任何 4s 窗口内都有有意义的变化。
- 结论场景的版式要互相不同。例如第一章结论用左右二分，第二章结论改用上下两条"道路分岔"。

示例：

```markdown
### s05 Q2 引入（89.06–106.12）
- 章节卡：「02」+「画图技能：重叠吗？」，0.9s 后归位到 HUD。
- `archify` 与 `diagram-design` 两个名牌。⟨archify⟩⟨diagram design⟩。
- ⟨有⟩：两个大圆（韦恩图，细线描边、填充极淡）从两侧靠拢重叠，交集区域填充浅浅的章节色。
- ⟨架构图⟩⟨流程图⟩⟨时序图⟩：图型小标签依次落进交集，每个标签带一个极简线框图示，阻尼 0.8 的轻微弹性。
- ⟨区别在做法⟩：两个圆沿水平方向拉开，交集消失。
- 退场：左圆缩成 s06 的起点节点（形变）。
```

片头与片尾：片头 0–0.8s 只有背景亮起，标题逐字模糊入场，再展开全片的问题或章节"轨道"。
片尾呼应片头，把每个问题的答案短语挂在对应轨道后面，最后收拢渐暗，最后一帧至少保持 2s。
